# Story 1.3: User Roles

**Status:** Ready for Review

**As a** system,
**I want** to assign roles to users (Administrator, Manager, Collaborator),
**so that** I can control access to different features.

## Acceptance Criteria
1.  The `User` model includes a `role` attribute.
2.  The default role on sign-up is "Collaborator".
3.  Backend services check user roles before performing actions.

## Dev Notes

### Previous Story Insights
Story 1.2 (User Authentication) is assumed to be complete, providing user registration and login functionality.

### Data Models
*   **User:** The `User` model should be updated to include a `role` attribute of type enum (`ADMINISTRATOR`, `MANAGER`, `COLLABORATOR`). [Source: architecture/data-models.md]

### API Specifications
*   No new endpoints are required for this story, but existing endpoints will need to be secured based on user roles.

### Component Specifications
*   No new UI components are required for this story.

### File Locations
*   **Backend:** `apps/api/src/main/java/com/taskflow/auth/model/User.java`, `apps/api/src/main/java/com/taskflow/config/SecurityConfig.java`

### Testing Requirements
*   **Backend:** Unit tests to verify that services correctly check user roles. Integration tests to verify that endpoints are correctly secured based on roles. [Source: architecture/tech-stack.md - Backend Testing: JUnit]

### Technical Constraints
*   **Backend Security:** Spring Security should be used to implement role-based access control. [Source: architecture/security-and-performance.md]

## Tasks / Subtasks

- [x] **Backend: Update User Model:** Add the `role` attribute to the `User` entity. (AC: 1)
- [x] **Backend: Update Registration Logic:** Set the default role to "Collaborator" when a new user registers. (AC: 2)
- [x] **Backend: Implement Role-Based Access Control:** Use Spring Security's annotations (e.g., `@PreAuthorize`) to secure endpoints based on user roles. For example, project creation might be restricted to "Manager" or "Administrator". (AC: 3)
- [x] **Backend: Write Unit Tests:** For role-based access control logic in services.
- [x] **Backend: Write Integration Tests:** To verify that endpoints are correctly secured based on user roles.
