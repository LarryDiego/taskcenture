# Story 1.2: User Authentication

**Status:** Ready for Review

**As a** user,
**I want** to be able to sign up and log in to the application,
**so that** I can access my tasks and projects.

## Acceptance Criteria
1.  A user can register with a username, email, and password.
2.  A user can log in with their email and password.
3.  The system returns a JWT upon successful login.
4.  The backend protects endpoints, requiring a valid JWT for access.

## Dev Notes

### Previous Story Insights
Story 1.1 (Project Setup) is assumed to be complete, providing the basic monorepo structure with frontend and backend applications.

### Data Models
*   **User:** `{ id: string; username: string; email: string; role: 'ADMINISTRATOR' | 'MANAGER' | 'COLLABORATOR'; }` [Source: architecture/data-models.md]

### API Specifications
*   **Login Endpoint:** `POST /api/auth/login` [Source: architecture/api-specification.md]
    *   Request Body: `{ email: string, password: string }`
    *   Response: `{ token: string }`
*   **Registration Endpoint:** (Implicitly required by AC 1) A `POST /api/auth/register` endpoint will be needed.
*   **Protected Endpoints:** Backend endpoints should require a valid JWT.

### Component Specifications
*   **Frontend:** Login and Registration forms.

### File Locations
*   **Frontend:** `apps/web/src/pages/auth/Login.tsx`, `apps/web/src/pages/auth/Register.tsx`
*   **Backend:** `apps/api/src/main/java/com/taskflow/auth/controller/AuthController.java`, `apps/api/src/main/java/com/taskflow/auth/service/AuthService.java`, `apps/api/src/main/java/com/taskflow/auth/model/User.java`

### Testing Requirements
*   **Backend:** Unit tests for authentication service, integration tests for login/registration endpoints. [Source: architecture/tech-stack.md - Backend Testing: JUnit]
*   **Frontend:** Unit tests for login/registration components.

### Technical Constraints
*   **Authentication:** JWT-based. [Source: architecture/tech-stack.md]
*   **Password Hashing:** BCrypt. [Source: architecture/security-and-performance.md]
*   **Backend Security:** Spring Security for protecting endpoints. [Source: architecture/security-and-performance.md]

## Tasks / Subtasks

- [x] **Backend: Implement User Model:** Create `User` entity with `id`, `username`, `email`, `password` (hashed), and `role`. (AC: 1)
- [x] **Backend: Implement Registration Endpoint:** Create `POST /api/auth/register` to allow new user registration. Hash passwords using BCrypt. (AC: 1)
- [x] **Backend: Implement Login Endpoint:** Create `POST /api/auth/login` to authenticate users and return a JWT. (AC: 2, 3)
- [x] **Backend: Configure Spring Security:** Set up Spring Security to protect API endpoints and validate JWTs. (AC: 4)
- [x] **Frontend: Create Login Component:** Develop a React component for user login. (AC: 2)
- [x] **Frontend: Create Registration Component:** Develop a React component for user registration. (AC: 1)
- [x] **Frontend: Integrate Authentication API:** Connect login and registration forms to the backend API.
- [x] **Frontend: Handle JWT:** Store and use the JWT for authenticated requests.
- [x] **Backend: Write Unit Tests:** For authentication service.
- [x] **Backend: Write Integration Tests:** For login and registration endpoints.
- [x] **Frontend: Write Unit Tests:** For login and registration components.
