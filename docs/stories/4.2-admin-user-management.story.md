# Story 4.2: Admin User Management

**Status:** Ready for Review

**As a** an administrator,
**I want** to manage users and their roles,
**so that** I can control access to the system.

## Acceptance Criteria
1.  An admin can view a list of all users.
2.  An admin can change the role of any user.
3.  An admin can deactivate or delete a user.

## Dev Notes

### Previous Story Insights
Story 4.1 (Export Reports) is assumed to be complete.

### Data Models
*   **User:** `{ id: string; username: string; email: string; role: 'ADMINISTRATOR' | 'MANAGER' | 'COLLABORATOR'; }` [Source: architecture/data-models.md]

### API Specifications
*   **Get All Users:** `GET /api/admin/users`. Requires "Administrator" role.
*   **Update User Role:** `PUT /api/admin/users/{userId}/role` with `{ role: string }`. Requires "Administrator" role.
*   **Delete User:** `DELETE /api/admin/users/{userId}`. Requires "Administrator" role.

### Component Specifications
*   **Frontend:** Admin User Management page, User list table, Role selection dropdown, Delete user confirmation modal.

### File Locations
*   **Frontend:** `apps/web/src/pages/admin/UserManagement.tsx`
*   **Backend:** `apps/api/src/main/java/com/taskflow/admin/controller/AdminController.java`, `apps/api/src/main/java/com/taskflow/admin/service/AdminService.java`

### Testing Requirements
*   **Backend:** Unit tests for admin service, integration tests for user management endpoints, including role-based access control.
*   **Frontend:** Unit tests for admin components, integration tests for user management functionality.

### Technical Constraints
*   **Backend Security:** Role-based access control (Administrator role for all endpoints). [Source: architecture/security-and-performance.md]
