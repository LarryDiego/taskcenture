# Story 2.1: Project CRUD

**Status:** Ready for Review

**As a** manager,
**I want** to create, read, update, and delete projects,
**so that** I can organize tasks into different initiatives.

## Acceptance Criteria
1.  An authenticated user with the "Manager" role can create a new project with a name and description.
2.  Users can view a list of all projects they are a member of.
3.  A project's name and description can be updated.
4.  A project can be deleted (and its tasks archived or deleted).

## Dev Notes

### Previous Story Insights
Epic 1 (Foundation & User Management) is assumed to be complete, providing the basic monorepo structure, user authentication, and role management.

### Data Models
*   **Project:** `{ id: string; name: string; description: string; tasks: Task[]; }` [Source: architecture/data-models.md]
*   **User:** Projects will likely have a relationship with users (e.g., owner, members).

### API Specifications
*   **Create Project:** `POST /api/projects` with `{ name: string, description: string }`. Requires "Manager" role.
*   **Get All Projects:** `GET /api/projects` [Source: architecture/api-specification.md]
*   **Get Project by ID:** `GET /api/projects/{projectId}`
*   **Update Project:** `PUT /api/projects/{projectId}` with `{ name: string, description: string }`. Requires "Manager" role.
*   **Delete Project:** `DELETE /api/projects/{projectId}`. Requires "Manager" role.

### Component Specifications
*   **Frontend:** Project list view, Project creation form (modal/page), Project detail view, Project edit form.

### File Locations
*   **Frontend:** `apps/web/src/pages/projects/`, `apps/web/src/components/projects/`
*   **Backend:** `apps/api/src/main/java/com/taskflow.project/controller/ProjectController.java`, `apps/api/src/main/java/com/taskflow.project/service/ProjectService.java`, `apps/api/src/main/java/com/taskflow.project/model/Project.java`

### Testing Requirements
*   **Backend:** Unit tests for project service, integration tests for project CRUD endpoints, including role-based access control. [Source: architecture/tech-stack.md - Backend Testing: JUnit]
*   **Frontend:** Unit tests for project components, integration tests for project CRUD functionality.

### Technical Constraints
*   **Backend Security:** Role-based access control (Manager role for project creation/update/delete). [Source: architecture/security-and-performance.md]
